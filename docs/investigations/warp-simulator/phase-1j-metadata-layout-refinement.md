## 问题原因与资源调查

原生 Star3／4／5 的画布都是 640×128，但前三／四颗星之后的区域完全透明。将同宽画布居中会使三星、四星可见内容偏左；强制三档图片等宽又会改变单颗星的大小。原三个等高纵向槽位则把图标和星级分散到整张卡片高度，光锥空属性槽及单抽高度进一步放大松散感。

从锁定的 StarRailRes Commit `dbe8cdfcfb0bf657b9fe1cf92d5537f118ccb487` 的 Git 对象读取三张原图，用 Sharp 0.35.3 检查 RGBA、Alpha 和透明裁切边界。未使用或修改来源工作区图片。

| 资源  | 画布／通道    | 非零 Alpha 边界（含端点） | 裁切矩形 left,top,width,height | 派生尺寸 | 派生字节 |
| ----- | ------------- | ------------------------- | ------------------------------ | -------- | -------: |
| Star3 | 640×128，RGBA | x=0–383、y=0–127          | 0,0,384,128                    | 196×68   |    7,860 |
| Star4 | 640×128，RGBA | x=0–511、y=0–127          | 0,0,512,128                    | 260×68   |    9,736 |
| Star5 | 640×128，RGBA | x=0–639、y=0–127          | 0,0,640,128                    | 324×68   |   11,772 |

三档源图中的每个 128×128 星星单元原始 RGBA 一致。Alpha 边界触及源图上下边缘，不能使用有损透明阈值进一步收紧高度；本轮使用 threshold 0，保留包括 Alpha=1 在内的柔光像素。

## 裁切、编码与追溯

新增独立 `card-stars` 用途，只供结果卡选择；原 201 张 Warp 图片及其 URL 均保留。处理顺序为：

1. 扫描所有非零 Alpha，取得完整边界；用 Sharp `trim({ threshold: 0 })` 的尺寸和偏移交叉核对。只允许丢弃完全透明像素。
2. 验证裁切宽度等于星数乘以内容高度、每颗星单元相同，且三档的源高度及单元内容一致。空图、非 RGBA Alpha、异常比例或单元不一致时中止更新。
3. 按该边界 extract，等比缩至内容高 64px、withoutEnlargement；随后四边各加 2px 透明安全边，WebP quality 90、alphaQuality 100。
4. 输出宽度为星数×64＋4，高度均为 68。缩放与添加安全边的顺序明确，不能把 Sharp 的 extend 当作缩放前操作，以免改变最终尺寸。

这样既去掉无星星的右侧区域，也保留柔光与安全边。三档按自身宽高比居中，星数增加只增加内容宽度；没有把裁切后的图片拉成统一宽度，也没有运行时裁切、CSS 位移补偿或修改原始美术。三张实际 WebP 已静态查看，星数完整且单颗星视觉尺寸一致；卡片内最终光学效果留待浏览器人工比较。

Source Lock 转换版本升为 3，来源 Commit 不变，新增 cardStars 的 method／threshold／contentHeight／padding／quality。Manifest 升为 schemaVersion 3，每个 card-stars 转换记录实际 crop；转换键包含源 SHA-256、card-stars-v1 配方标识、裁切方法／阈值／矩形、内容高度、安全边及编码质量。新输出仍按转换键 SHA-256 命名并去重；其他用途的旧转换键不变。

Validator 补充安全的来源路径、整数裁切边界、星数比例、统一源高度、无放大尺寸、安全边、转换键、Catalog 对应尺寸、引用覆盖、哈希和严格文件清单检查。普通验证不读取来源图；Alpha 完整性由显式生成和合成测试核对。更新仍使用原独占锁、staging 校验、两个自有目录发布与失败回滚；共享头像目录不搬移。

新增缺图测试还发现原生成器会把缺失的旧星级写成 undefined 映射，导致序列化前校验失败。现改为仅登记实际存在的旧星级和高清 Star5；缺失时省略映射并保留诊断。正式已有图片不受影响。

## Metadata 布局与尺寸

结果卡仍为约 2.1:1 横向外框。右区采用 minmax(80px, 30%)，横向 Padding 6px、纵向 8px；分隔线从稀有度色 28% 混色减弱为 14%。外层仍 overflow visible，稀有度边框、Glow、图片适配策略、3–4–3 和入场动画未改。

右区通过可收缩 Grid 把两行信息簇整体水平、垂直居中。第一行是命途与角色属性，Flex 水平排列、间距 8px；光锥只渲染命途，整行自然居中，不保留属性空槽。第二行是裁切星级。UP 继续独立定位，不参与信息簇布局。

| 参数                     |      十连 |       单抽 |
| ------------------------ | --------: | ---------: |
| 图标目标尺寸             |      32px |       40px |
| 图标组与星级间距         |      14px |       20px |
| 星级目标高度（含安全边） |      18px |       23px |
| 对应五星最大宽度         | 约 85.8px | 约 109.6px |
| 单抽卡片最大宽           |         — |   原 620px |

Metadata 建立 inline-size 查询容器；图标共同按“可用宽度减 8px，再除以二”约束，光锥单图标不额外放大。图标组明确宽度 100%，避免百分比宽度与 Flex 固有尺寸互相依赖。两行间距是上述固定参数，不按卡片高度分配剩余空间。

三档星级共用有效高度 `min(目标高度, 100cqi / 五星裁切宽高比)`，然后按各自图片宽高比计算宽度。即使窄卡碰到宽度上限，三档也同时缩小，不会只有五星变小；单颗星的内容高度分别约为 16.94px／21.65px，随共同宽度限制一致降低。自然宽高比替代卡片模式的旧 5:1；其他调用仍使用原规则。Tooltip、ARIA、整卡详情事件和焦点行为保留。

## 维护者本地验收

运行 `npm run dev`，打开 `http://127.0.0.1:5173/tests/manual/warp-results/index.html`，端口以实际 Vite 输出为准。该页使用固定展示记录，不调用抽卡引擎、不保存正式会话。合成五星光锥只用于样式比较，不进入生产数据。

1. 对比“全三星十连”“四星角色／光锥混排”“三种稀有度混排”：三星、四星、五星可见星星内容分别居中，单颗星大小相同，五颗星完整，不因 UP 改变定位。
2. 分别选择三星光锥、四星角色、五星角色单抽。光锥命途自然居中，角色命途与属性并排；图标组和星级是紧凑整体，单抽变宽／变高时两行不会被拉散。可在开发工具临时调整单卡高度，仅用于验收固定行距。
3. 检查 1440、1920、1024、640、390、320px，中英文及缩放 80%／100%／125%／150%。重点检查四卡并排、断点附近和最窄单列的图标间距、共同缩放、星级外缘、横向溢出和右区宽度。
4. 比较角色面部、光锥完整封面、3–4–3 位置、紫金 Glow 和焦点轮廓，应延续已验收版本；右区适度加宽是本轮明确选择，图片 cover／contain 与定位规则没有变化。
5. “缺图／请求失败／极端宽高比”包含缺失裁切星级；“单抽高清与轻量图片均请求失败”同时包含坏星级 URL。检查中性占位、完整 ARIA／三行 Tooltip、触屏和 Enter／Space 打开详情、关闭后恢复焦点。
6. 打开历史和详情，对比原星级显示、字号、分页和交互；播放单抽及多五星演出，命途＋Star5 同步阶段、高清图片和确认队列应与 Phase 1I 相同。网络中确认结果卡使用 cardStars，历史／详情／演出仍使用原对应资源。
7. 正式页面实际抽取并切换语言、开关详情／Drawer、退出演出，确认历史及保底保持已提交结果；测试页人工记录不能当作合法抽卡结果。
