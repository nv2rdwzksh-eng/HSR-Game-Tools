# 货币战争羁绊优化器

提供网页和独立 CLI，只计算角色和星徽带来的羁绊人数。它先最大化所选任务完成数，再按所选模式最小化角色数量（少人，默认）或星徽消耗（少星徽），不引入第三个优化目标，也不优化战斗力、费用或养成成本。没有后端、方案持久化、分享或导入导出功能。

## 网页使用

从首页打开「货币战争羁绊优化器」，或直接访问 `/currency-wars`。网页默认 13 槽、18 枚星徽、排除专家，25 项目标任务初始均不选中。默认优化目标为少人。每次请求固定使用 60 秒求解预算，不提供时限输入。

配置使用 Astral UI 浅色面板，包含「目标任务」和「设置」两个页签。搜索框使用放大镜图标，搜索按羁绊名称、任务 ID、羁绊 ID 和人数门槛过滤显示；全选／清空使用同排等宽按钮，分别带勾选／清空图标，清空使用 danger 样式；操作始终作用于全部任务，不受搜索影响。已选数量位于搜索框上方，搜索和批量按钮不随列表滚动。目标任务展示羁绊图标、名称和人数门槛，开关按稳定任务 ID 即时生效，不再使用选择弹窗或确认草稿。列表占据面板剩余空间独立纵向滚动，上下边缘按剩余内容渐隐；关闭全部任务后提示并禁用开始。设置依次排列槽位、星徽预算、专家、优化目标。两个数量滑块分别允许 1～13 槽、12～39 枚星徽，专家默认不勾选。底部通过同组 Radio 互斥选择少人／少星徽；槽位与星徽预算均为上限，无须用满。低槽位无法完成部分任务属于正常优化场景，不拒绝请求。切换页签保留配置，开始与取消操作始终固定于面板 Footer，设置页也使用独立 HFadeContainer。

求解仍在独立 Web Worker 执行，显示加载状态而不伪造百分比。等待期间可编辑条件，重复启动被禁用；取消直接终止 Worker，重新开始会创建新实例。离开页面释放运行实例。配置和语言变化不会自动求解。

每次仅返回一个独立验证的推荐阵容。结果分为推荐阵容、羁绊详情、星徽需求三个内容页签；切换不重新求解。新有效结果默认进入推荐阵容并关闭旧角色详情。结果 Header 和 Tabs 固定，每个 Tab 的 HFadeContainer 填满剩余高度，仅内容纵向滚动，使用上下渐隐；切换页签从顶部开始，不改变面板高度。内容不足时保留空白，不拉伸内容。Tab 内不再重复显示栏目标题或通用配方说明。

结果复用原有角色头像、费用背景和三个星徽槽。阵容网格左对齐，默认卡片宽 128px，手机宽 104px；仅在展示副本上按费用降序、形态 ID 升序排序。点击或键盘激活头像打开 Astral UI HModal。illustration 显示圆形头像、实际形态费用及站位，title 显示角色名称；默认内容统一显示独立评估 finalTraits（按 ID 去重排序）、实际佩戴星徽图标及名称、特殊机制，无区域标题或多层 Card，以细分隔线区分。无星徽显示 —。领航员目标直接取 navigatorTarget，使用目标真实头像与实际形态费用背景；布洛妮娅显示确定归属图标，平局如实未归属并保留警告。Footer 仅一个 cross 关闭 HButton，右上角保留原生关闭。窄屏上下布局，正文内部滚动、Footer 常驻。求解结果标题旁紧邻显示绿色 HBadge 显示完成任务／该次任务总数，切换内容页仍可见，始终读取上次有效结果及其请求；使用星徽摘要已移除，实际佩戴与需求仍在对应页签中展示。

羁绊详情按稳定羁绊 ID 合并目标任务与实际已激活羁绊。顺序为未激活目标、已激活目标、其他已激活羁绊；目标组沿用任务顺序，其他组沿用快照顺序。激活依据真实激活门槛，与任务是否完成分开判断。左侧第一行显示图标、名称及紧随其后的人数；目标为实际／要求，其他仅显示实际人数。第二行与名称对齐，显示绿色「目标任务」及对应状态。未激活目标使用灰色「未激活羁绊」，不重复显示未完成；已激活目标显示完成／未完成，低门槛已完成但尚未激活时保留完成信息。同一羁绊多个任务保留全部门槛与各自状态。右侧所有贡献成员头像常驻、靠右对齐，使用实际形态费用对应的同一套角色卡背景色，资源及缺图回退保持不变；空间不足时自动换行，不折叠或横向溢出。姓名通过 title、替代文本和 ARIA 获取。角色卡名称下直接显示开拓者前台／后台、姬子·启行的真实领航员目标（无目标时明确提示），以及布洛妮娅的已确认羁绊或平局未归属状态；完整机制信息仍在角色详情中，平局警告继续保留。白色单色羁绊图标在浅色面板中转换为深色，头像、星徽和材料保持原色。

页面不展示状态码、耗时分解、证明、求解界限或 Gap 等诊断详情，底层保留单方案状态、上界与 Gap 等必要诊断。未证明最优和模型警告直接可见。条件改变后保留旧结果并标记过期；新求解失败、无结果或取消时保留上次有效结果并标明历史状态。主动取消不保留本轮未返回的局部结果。

界面提示提供简体中文和英文，游戏专名继续沿用中文快照。桌面配置栏宽 340px，960～1099px 收至 300px。宽度至少 960px、高度至少 640px 时，通过本页限定的 CSS Grid／Flex 使用 100dvh，自动扣除实际站点 Header、页面标题和边距；左右面板等高填满可用空间，列表与结果内部滚动，正常桌面使用无需整页纵向滚动。较矮桌面继续双栏，低于 960px 上下排列；两种回退布局均允许页面滚动，每个面板高度为 max(30rem, 70dvh)，保证内容可访问。主题只作用于显式标记的面板和详情弹窗，不修改网站 Header 或其他工具；接入和维护见下节。配置与结果 HTabPanels 使用原生切换和高度动画，本页 HButton 启用星光、HModal 启用原生进出场与页脚动画，遵守系统 Reduced Motion 和 data-h-motion。开始按钮使用 Lucide Play 实心三角形，Loading 时隐藏 Play，保留 Spinner。

## Astral UI 接入与同步

依赖为 `astral-ui: file:vendor/astral-ui`，源码包与 npm 锁文件一同纳入版本管理。全新环境只需 `npm ci`，不需要相邻 fork、额外构建产物或运行时网络。库使用 Vue peer dependency，与应用共用 Vue。

页面导入 `astral-ui/components` 和 `astral-ui/scoped-theme.css`。前者不加载全局主题，后者仅影响 `.h-theme`。不要改用默认入口，否则会加载全局 `theme.css`。业务局部变量位于页面的 `ui/theme.css`；HModal 将 class 等属性透传至 body 中的遮罩根节点，显式添加 h-theme / currency-theme；closeLabel 使用双语关闭标签。退出期间保留内容与滚动锁，after-leave 后清除角色并恢复焦点，原触发项已被新结果移除时回到结果页签；快速重开和卸载均不会遗留锁定。

来源 commit、文件 SHA-256、已有文件的未提交扩展补丁及新增源码清单保存在 `vendor/astral-ui/provenance.json` 和 `local-changes.patch`。本次基于 fork Commit `0dce0fad3bc993708d62598e315210adbcfb7373`，记录的哈希还包含未提交扩展，不能仅凭 commit 复现这些字节。上游声明保留，不为第三方源码推定许可证。本轮仅在本仓库副本扩展 HModal 的属性透传、closeLabel、after-leave 和关闭生命周期防护；扩展同时记录在补丁与文件哈希中。后续从 fork 同步前须先合入这些扩展，避免被同步覆盖。

显式更新时先在本地 fork 修改组件、文档和测试，检查通过后执行：

```bash
npm run sync:astral-ui -- --source /path/to/local/astral-ui
npm run validate:astral-ui
```

同步脚本只操作本仓库的 vendor 快照，不修改来源仓库、不创建 Git 子模块、不自动提交或联网。同步后重新验证类型、测试、格式和构建并检查差异。普通安装、测试和构建不执行同步。

## 星徽需求

网页结果第三个内容页签展示「星徽需求」。统计只遍历当前单方案的 `lineup.members[].emblemIds`，按稳定星徽 ID 累加；仅展示实际使用项，按数量降序、ID 升序排列，总数等于该方案的 `evaluation.emblemCount`。切换内容页不重新求解；过期、历史或上次有效结果继续显示原结果的数据，不读取正在编辑的配置。零星徽方案显示空状态。

每行显示星徽图标、名称、需求数量及该赛季的全部合法合成配方。每条配方合成一个星徽，多条配方之间的「或」表示替代关系；例如欢愉星徽可使用垃圾袋与红钻，或垃圾袋与蓝钻，不需要同时消耗两组材料。没有当前赛季配方的星徽仍正常计数，合成区域仅显示 `—`；这只表示经过权威数据核对无配方，数据提取或校验失败会明确报错。

本功能不汇总材料总量，不处理库存、合成次数、差额、配方选择或最低成本。材料名称来自锁定游戏数据，所有图片使用本地资源；缺图时保留名称并显示中性占位。640px 及以下把配方放到该行下方，材料允许换行。

此功能仅扩充网页结果展示，CLI 的单方案输出与求解规则保持不变。

## 控制台使用

使用项目要求的 Node.js 24.x（最低 24.12）与 npm，按锁文件安装依赖后，从仓库根目录执行：

```bash
npm run currency-wars
```

TTY 终端会依次询问优化目标、槽位、星徽预算、是否包含专家、任务子集和求解时限。通过命令行提供的选项不重复询问；非 TTY 自动使用非交互模式。

默认 13 槽、12 星徽、排除专家、30 秒。正式用户模式允许 1～13 槽；预算接受至少 12 的安全整数，不设人为上限，实际最多使用 `3 × 槽位` 个星徽。时限必须为正的有限秒数，是整个请求的时间预算，包含 Wasm 初始化、建模、求解和验证；允许少量不可避免的原生求解停止与调度开销。CLI 保留单方案输出，使用相同规则、验证器及预算实现。

```bash
npm run currency-wars -- --non-interactive --slots 13 --emblems 18 --time-limit 30 --select all
npm run currency-wars -- --tasks ./my-tasks.json --select task-001,3 --include-experts
npm run currency-wars -- --objective min-emblems --non-interactive --select all
npm run currency-wars -- --help
```

`--objective` 接受 `min-roles` 或 `min-emblems`，默认 `min-roles`，非法值以输入错误退出。交互模式也可选择优化目标。`--tasks` 路径相对当前工作目录解析；未指定时使用本仓库 `data/currency-wars/tasks.json`。`--select` 支持以逗号分隔的任务 ID、从 1 开始的编号或 `all`；先匹配任务 ID，再解析编号，重复选择只计一次。非交互模式默认选择全部任务。

结果显示求解状态、任务完成数、角色数量、星徽使用量、耗时，以及阵容、激活羁绊贡献者和逐项任务人数。角色与羁绊均带稳定 ID，羁绊同时标注阵营、流派或独立类型。

退出码：`0` 为成功输出最优／可行结果或空任务提示，`1` 为无结果／求解器报告不可行，`2` 为输入、数据、模型或结果验证错误。结果未通过独立验证时不会作为可用方案输出。可行但未证明最优的方案会明确标注；不会把超时等同于最优。

## 正式任务列表

`data/currency-wars/tasks.json` 已按用户提供的完整清单录入 25 项任务，保持原始顺序，稳定 ID 为 `task-001` 至 `task-025`。程序仍支持空列表：正常提示并退出，不启动求解器。

每项任务保存稳定 ID、羁绊数字 ID 和目标人数；以下为正式列表的前两项：

```json
[
  { "id": "task-001", "traitId": 1007, "requiredCount": 7 },
  { "id": "task-002", "traitId": 1008, "requiredCount": 6 }
]
```

任务 ID 必须为非空、无首尾空白且全文件唯一的字符串；羁绊 ID 必须存在，人数为正的安全整数。未知字段、重复任务 ID 和非法数据被拒绝。同一羁绊不同人数门槛可同时完成；超过可达人数的门槛保留为未完成。名称不能代替数字 ID。

技术演示任务单独保存在 `tests/fixtures/currency-wars/demo-tasks.json`，不代表真实游戏任务，不会复制进正式文件：

```bash
npm run currency-wars -- --non-interactive --tasks tests/fixtures/currency-wars/demo-tasks.json --slots 13 --emblems 12 --time-limit 5
```

演示任务仅用于技术验证；阵容、目标值和耗时以所选优化模式下的实际执行为准。

## 羁绊类型与规则

快照显式区分三类：`camp`（阵营）、`class`（流派）、`unique`（独立）。普通阵营与流派人数都按每名具有该羁绊的角色贡献 1 人计算，但类型在特殊机制中有严格差别。

| 类型 | 例子                                    | 姬子·启行能否继承                    |
| ---- | --------------------------------------- | ------------------------------------ |
| 阵营 | 列车同行 1001、仙舟 1007、盛会之星 1010 | 否                                   |
| 流派 | 能量 2004、减益 2007、持续伤害 2008     | 仅目标固有流派及开拓者明确授予的流派 |
| 独立 | 大守护者 3001、领航员 3007              | 否                                   |

星徽必须在快照中实际存在。每名上场角色最多三个，不能重复同种星徽、不能获得已有羁绊；同一种星徽可给不同角色佩戴，受全局预算限制。独立羁绊不虚构星徽补足。全部真实星徽都会进入候选，包括不直接对应目标任务、但能赋予领航员资格的列车同行星徽。

- **姬子·启行**可选择另一名上场角色作为目标；目标必须具有列车同行 1001，可以由固有羁绊或所佩戴星徽提供。选择后必须同时取得目标的全部固有流派，不是任意挑选其中一种；目标通过星徽新增的流派、阵营和独立羁绊均不继承。目标为任一开拓者形态（8007 或 8009）时，继承集合额外并入能量 2004 和欢愉 2012，不受其前后台固有流派互斥影响，也不要求目标佩戴另一流派星徽；合并后每种流派只继承一次。开拓者的其他流派星徽仍不被继承。若任一继承流派已由姬子自身或星徽取得，则整项配置非法，不用去重掩盖冲突；双方佩戴同一种未被继承的流派星徽则不构成继承冲突。允许不选择目标。
- **常规景元**仅允许 `1204`（5 费）进入候选；`12041`（1 费）、`12042`（3 费）仍如实保留于原始快照和费用目录。模型和独立校验器共用集中候选资格判断。
- **开拓者**的两个形态共用身份；前台固有能量，后台固有欢愉。可以佩戴另一流派星徽，同时获得两者，但不能把两个形态同时上场。
- **布洛妮娅**按其他角色的最终人数（包括星徽与合法领航员继承）比较贝洛伯格、燃血，排除自身的全部贡献，严格加入人数较多一侧。平局保留大守护者，两侧不计她的人数，并提示结果为保守下界；她的星徽必须在两种可能归属下都合法。平局模型中的 `11011:tie` 是工具状态，不是上游角色 ID。
- **初版禁止布洛妮娅成为领航员目标**。这是用户选定的限制，避免未确认的形态／继承反馈关系；即使给她列车同行星徽也不允许。
- **白厄**取得其他已激活羁绊效果不增加人数，故不计作那些羁绊的成员。其他战斗效果、复制首件装备和遭遇／模块修改不建模。

所有最优性证明只针对上述快照与本版规则。未知的游戏平局规则及禁止的目标组合意味着此原型不是所有游戏机制下的完整全局最优证明。

## 数据快照与显式提取

来源为 [TurnBasedGameData](https://github.com/DimbreathBot/TurnBasedGameData)，锁定 Commit `312b4597691e0a29cf9828a15b592757dba86949`，4.6.0、Season 1。保留既有[来源致谢](third-party/README.md)。快照包含 77 条原始角色配置、78 个规范化形态、71 个身份（排除专家后 62 个）、33 种羁绊和 22 种星徽。

`scripts/currency-wars/source-lock.json` 维护固定来源与审阅过的阵营 ID。此 Commit 中 `TraitType: "Class"` 为流派，`"Unique"` 为独立；阵营条目省略该字段，仅锁定名单中的缺省类型映射为阵营。未知类型、未审阅切换与不支持的星徽规则会阻止提取，不从中文名称或数字范围推断类型。

提取读取 GridFight 角色、羁绊、星徽、门槛、形态、效果调查表、物品名、AvatarConfig／AvatarConfigLD 与中文 TextMap。Hash 从 JSON 原始整数词法保存为字符串。身份按相同 AvatarID 及显式切换关系合并；不会把不同 AvatarID 的剧情人物形态擅自合并。

正常求解、安装、测试、构建不联网、不读取相邻仓库，也不自动生成数据。显式维护命令：

```bash
npm run validate:currency-wars
npm run extract:currency-wars -- --root ../TurnBasedGameData
```

提取要求来源是干净的 Git 根目录且 HEAD 等于锁定 Commit，不 fetch 或切分支，只写本工具的快照和 Manifest；**不会写入或清空任务文件**。Manifest 记录输入文件 SHA-256、来源、转换版本、规则说明、统计和输出哈希。提取后审阅变更并执行快照检查、相关测试。生成 JSON 用固定序列化，不能交给 Prettier 改写。

### Worker 与 WASM

浏览器 Worker 和 CLI 都调用唯一单方案入口 `solveCurrencyWars`。通过 `createHighsSolver(loader)` 仅替换 HiGHS 加载方法。求解选项、状态解释、解码与独立验证没有另写一套。每次运行通过结构化消息传递请求与结果，带运行 ID，旧实例响应不会覆盖新状态。

Vite 以 ES module 打包 Worker，通过 `highs/runtime?url` 输出带哈希的本地 WASM；浏览器适配器向 HiGHS 提供 `locateFile`。WASM 只在用户发起求解时由 Worker 初始化，不从 CDN 下载。根路径与子路径构建均可使用。

构建时可能看到 highs 包中受环境分支保护的 `node:module` 外置化提示，以及同包静态／动态导入提示；浏览器分支不会执行 Node 加载逻辑，也没有添加 Node polyfill。用以下探针实际执行构建产物和 WASM，不能仅凭 build 成功判断初始化可用：

```bash
npm run build
npm run verify:currency-wars-browser
npm run build -- --base /hsr/ --outDir .cache/currency-wars-subpath
npm run verify:currency-wars-browser -- --dist .cache/currency-wars-subpath --base /hsr/
```

探针在独立 Node 线程的无 Node 全局 VM 中执行真实浏览器 Worker 代码，fetch 只读取本地构建的 WASM，验证结果及主线程心跳；它不启动浏览器，不等同于浏览器人工验收。HiGHS 许可证逐字保留于 `public/third-party/highs-LICENSE.txt` 并进入静态产物。

## 核心接口与验证

`src/tools/currency-wars/` 提供 Snapshot、Task、OptimizationObjective、OptimizationRequest、Lineup、Evaluation 和单方案 OptimizationResult，以及 buildModel、evaluateLineup、solveCurrencyWars。请求必须携带 objective、任务、槽位、预算、专家开关与时限。结果携带脱离表单的请求快照、状态、总耗时、至多一个阵容与评价，以及必要的 solverStatus、objectiveBound、gap。不存在多方案数组或兼容批次接口。

模型和计算器不读取文件、原始配置、Vue 或 CLI。计算器独立计算每名角色的羁绊来源、贡献人数、真实激活门槛、逐项任务完成状态及所选模式的目标值。求解封装核对全部二元列、模型约束、人数、任务标志和目标值，拒绝不完整／非整数／不一致的结果。穷举只用于小规模测试 Oracle。

HiGHS 1.15.3 通过 WASM 最大化 `W × 完成任务数 − 次目标数量`，相对与绝对 MIP Gap 均为零：

- 少人：`W = slots + 1`，只惩罚角色数，不惩罚星徽数。
- 少星徽：`W = min(emblemBudget, 3 × slots) + 1`，只惩罚星徽数，不惩罚角色数。

W 大于次目标的最大差值，因此多完成一项任务始终优于任何次目标收益。两个模式都不要求用满槽位或星徽；完全等价的最优阵容可以任选。输入同时检查整数与加权目标的安全数值范围。

仅求解器证明完整加权目标最优且结果通过独立验证时返回 optimal；受限求解检查 primal_solution_status 后读取 incumbent，验证合法则返回 feasible。即使完成全部任务，也不单独推导完整最优。上界和 Gap 均对应所选模式的完整目标。

### 单方案求解与时间预算

每个请求只建模并求解一次，剩余预算全部分配给这一个模型，不重试或切分候选预算。总耗时使用单调时钟；HiGHS runtime 惰性加载，原生模型运行前扣除加载与解析时间，并在 finally 中释放。原有特殊规则约束保持不变。

Session 保留 requestId、lastAttempt、lastValid、stale、historical；优化方向包含在请求快照与指纹中。任务或模式变化只标记过期，不自动求解；搜索和语言变化不改变请求。Worker 消息检查请求一致性、单方案结构和状态，并独立复算评价；非法消息、失败、无结果和取消均不替换上次有效结果。取消终止 Worker，旧实例响应不会覆盖新状态。
