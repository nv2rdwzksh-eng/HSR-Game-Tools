## 根因与修复

原 MILP 从目标的 `direct` 羁绊表达式计算继承，独立校验器从目标的 `finalTraits` 计算继承；两者都包含目标星徽新增的流派，因此会一致地高估人数，原独立验证无法发现这个共同的规则错误。

- [MILP 模型](../../src/tools/currency-wars/model.ts)改为从目标 `RoleForm.innateTraits` 筛选 Class，合并 `navigatorGrantedTraits(target)`，用 Set 去重；每种继承流派直接由目标选择变量决定，移除原先与目标星徽构造的 AND 辅助变量。
- [独立校验器](../../src/tools/currency-wars/evaluate.ts)单独从目标固有 Class 与特殊授予集合计算继承，不读取模型列或约束。目标自身的最终羁绊计算未改。
- 目标资格仍由 MILP 的 `direct`、校验器的 `finalTraits` 判断列车同行 1001，因而列车同行星徽仍能赋予资格。资格来源与可继承内容是不同规则。
- 开拓者 8007、8009 继续通过原有声明授予能量 2004 和欢愉 2012；固有与特殊授予重合只计一次。前后台身份互斥、开拓者自己的星徽、姬子固有／星徽与继承流派的冲突限制均保留。第三种星徽流派不继承，双方合法佩戴同一种未继承流派星徽不会产生继承冲突。

未改公开接口、HiGHS 1.15.3、Worker 协议、Batch 编排、完整配置 No-good Cut、排序或共享预算策略。布洛妮娅、角色选择和任务约束保留。

## 复现与回归覆盖

修改实现前先更新测试，实际运行五个相关测试文件：11 项按预期失败、47 项通过。失败涵盖普通目标、开拓者、真实 HiGHS、多方案和展示结果；没有删除旧行为测试来隐藏变化。

- 替换 `inherits every Class, including emblem Classes`：星徽列车同行资格仍合法，只继承目标固有 Class，不复制阵营、独立或星徽 Class；断言目标自身羁绊与贡献者。
- 增加五组小快照，覆盖固有／星徽列车同行、没有固有 Class、固有双 Class 加第三种星徽 Class。保留非法目标与继承冲突用例。
- 替换 `copies emblem Classes compulsorily`：两槽、姬子与固有列车同行／减益的目标、一枚星徽预算，要求减益两人和持续伤害两人。旧实现给目标佩戴持续伤害星徽即完成两项，目标值 `7 × 2 − 1 = 13`；修复后只能完成一项，最优零星徽、目标值 7，与穷举 Oracle 相同，并再次独立核验人数、任务及贡献者。
- 修改两个开拓者星徽继承旧用例：额外流派只贡献目标本人；能量、欢愉继续授予且不重复，姬子佩戴这两种星徽仍冲突，佩戴未被继承的流派合法。
- 新增真实 HiGHS Batch 回归，返回三个不同且逐一独立验证的配置，目标值依次为 7、6、6，均不误完成持续伤害两人任务。原有配置排除、时限、排序、单方案兼容及 Session 切换测试继续通过。
- 扩充椒丘真实数据展示测试：佩戴列车同行、护盾、欢愉星徽时，姬子额外羁绊只有减益、持续伤害；任务人数和贡献者正确，目标三个星徽仍正常展示。
