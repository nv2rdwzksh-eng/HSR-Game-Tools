# Phase 1B-1：真实 Action Planner 编辑器

实施及本地验收日期：2026-10-13。范围仅 HSR-Game-Tools；沿用已验收的 PrimeVue 视觉方案，未提交、推送或部署。

## 结论与功能边界

`/action-planner` 已从双状态原型转换为真实排轴编辑器。队伍、预算、五类引擎操作、排序和删除均提交到 `SimulationPlan`，随后调用现有引擎重算。自定义操作名称属于工具元数据，不影响模拟。八类需求流程均在浏览器通过真实表单执行，原有 67 项基础测试与 11 组迁移对照保留。

队列快照、箭头、名称、目录和诊断是派生展示。它们不构成第二份业务计划，也没有假提交。速度／事件示例由用户输入普通操作，不是自动角色技能模型。当前没有持久化，刷新即清空内存配置。

## 状态、身份和提交

`useActionPlanner` 持有一个 `PlannerDocument`：

- `plan`：唯一模拟输入，包含初始 Actor、PlanEvent 和预算。
- `metadata.customNames`：按 operation ID 保存非空自定义名称；删除操作或整组事件时清理。
- `metadata.characterIds`：初始 Actor ID 到规范化角色 ID 的关联，用于本地化名称和图片；替换角色后保留旧关联，便于失效锚点的名称展示。

模拟结果为 shallowRef，不复制为另一套可写配置。目录、诊断、不可达事件、执行时点预览和队列均从计划及结果派生。导航保存工作阶段、模式、所选锚点与队列游标；操作草稿是临时字段。

战斗配置只有“应用配置”才提交，未应用输入在工作阶段切换后保留。操作提交复用 `saveOperation`，移动复用 `moveOperation`，参与者和持续时间复用原有构建／校验辅助。只改操作名称时比较规范化内容，更新 metadata 而不重算。取消编辑及切换节点、工作阶段、导航模式丢弃操作草稿，不弹确认框。持续方式切换只解析当前可见参数。

编辑保留 operation ID，改速度保留 Actor ID，更换角色分配新 Actor ID。创建操作的 Actor／Scheduled Event 种类被锁定，实体改名不改变 ID。所有引用使用稳定 ID 与引擎 `anchorKey`；替换或删掉上游创建操作后保留原引用和真实诊断，不按名称自动改绑。

## 上下文、失败恢复与不可达配置

正常节点使用 NodeRecord.beforeEffects；战斗开始使用 startState。目标预览调用 `previewOperationState`，参数包含锚点、阶段与正在编辑的 operation ID，因而能看到同节点前序创建的参与者，并排除尚未执行的创建。

失败节点没有伪造 NodeRecord。工具用 `createInitialState`、`applyOperations`、`stepSimulation` 重放已成功前缀，再由引擎生成失败节点操作前上下文。失败发生在更早的步骤且上下文无法恢复时，返回 unavailable。没有手写 AV 推进、生命周期结算或队列逻辑。

不可达事件集中列出原锚点，可选中查看、删除单个操作或删除整组配置。没有可靠上下文时禁止添加／编辑，保留删除及顶部“战斗配置” Tab 修复入口。缩小预算、换角色或删动态实体不会迁移事件。运行时速度和到期诊断照实保留，错误默认展开。

## 表单与参与者

| 操作                              | 已接入的能力                                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------------------------- |
| advance／delay                    | 显式或动态集合目标、非负有限百分比、阶段、名称；提前无 100% UI 限制，沿用引擎归零／延后过满区别 |
| immediatelyAct                    | 真正的立即行动操作、合法目标与阶段，没有百分比字段                                              |
| addSpeedModifier                  | 正负固定值／基础速度百分比，指定或无限回合，具名共享倒计时                                      |
| spawnParticipant：Actor           | 实体名称、阵营、现有类别、基础／面板速度、有限／无限行动次数                                    |
| spawnParticipant：Scheduled Event | 独立实体名称、事件速度、单次触发                                                                |

所有表单统一提供自定义操作名称。创建操作名称与实体名称、速度效果名称与倒计时名称相互独立。空回合数／行动次数表示无限；多目标速度效果由引擎创建一个共享倒计时。结构、目标和字段校验失败不提交，运行时诊断允许通过原配置入口修复。

普通行动节点按行动前、动作后窗口展示和排序；战斗开始及事件触发没有阶段选择。移动只在同窗口内发生，阶段改变进入新窗口末尾。复杂字段拆为 EffectFields、ParticipantFields、TargetGrid；OperationEditor 负责类型、阶段、名称、预设及提交。

目标 Grid 包含真实角色、动态 Actor、敌方、召唤物、忆灵、事件与倒计时。合法性由 `targeting.ts` 决定，支持指定参与者及我方／敌方动态集合。倒计时只允许显式单目标提前／延后，不能混入多目标，不接受立即行动或速度效果。触发中的事件已离开合法目标集合。同名参与者按稳定 ID 排序派生 `#1/#2` 标签，不依赖队列位置。

## 命名和操作卡

`model/naming.ts` 是不依赖 Vue／DOM 的纯 Presentation 模块。自定义名称 trim 后优先；空白恢复自动标题，自动名称不写入计划。初始角色名来自当前语言的规范化快照；用户实体名及自定义操作名不翻译。

单目标显示名称，多目标显示数量；动态集合通过该操作实际执行位置的预览状态解析，行动变化排除当前活跃、已离队参与者，速度效果沿用相应合法对象。无法可靠解析时使用范围名称，不借初始队伍长度编造数量。支持正负速度、百分比、敌方／召唤物／忆灵／事件的中英文标题。

操作卡标题统一调用命名模块，图标表达操作语义，保留目标、速度生命周期及创建实体的必要信息。阶段作为分组标题，删除机械 Metadata 拼接及重复原型说明。Inspector 概览显示当前有效速度，便于观察到期后的状态。

## 箭头修正

旧原型隐藏计划在战斗开始提前三月七，而右侧局部卡配置对布洛妮娅的操作，两套状态没有联动。问题既有展示印象，也有业务输入分离，不能靠改颜色解决。

现在未来行动读取 record.actionChanges，当前队列读取对应 queue entry.actionChanges。纯函数 `actionDirections` 只保留 targetAnchor 匹配的 Trace，发生 AG 变化或 zeroAVInsertion 才显示相应方向；同一待行动的提前、延后可同时表达，不汇总为单一净方向。删除真实操作后重算，箭头随 Trace 消失。源节点配置图标拥有独立的“本节点配置了 N 个操作”可访问名称。

## 战斗配置与装备

默认四个空槽、无事件、60 节点／600 AV。全部 98 条角色快照复用轻量名称／别名搜索，并补充本地化命途形态匹配；开拓者男女形态标签明确区分。其他槽占用的角色 ID 禁选，不同形态按独立 ID 处理。选角色自动填入基础和面板速度，两者可分别编辑。预算硬上限 500 节点／100000 AV，非法输入留在草稿，已有事件保留。

舞舞舞 24%、翁瓦克 40%、翔鹰 25% 复用原有预设生成器，生成可编辑普通操作。翁瓦克只有战斗开始可选，不检查 120 SPD。实际浏览器发现预设空 ID 被当作编辑 ID，已修复为先构建全新草稿再赋值，并增加真实提交回归测试。没有装备专用引擎分支。
