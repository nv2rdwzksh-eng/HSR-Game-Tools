## 问题原因与修复

| 问题                 | 代码审阅结论                                                                                           | 本轮修复                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 命途、属性、星级漂移 | 原信息栏以 Flex 居中排列，光锥少一个属性，UP 又占用普通行，内容数量决定位置                            | 固定三个等高 Grid 槽位；光锥保留空属性槽；UP 独立绝对定位                                      |
| 紫／金 Glow 不明显   | 原边框使用较接近的亮度，只有一层低透明度柔和外光，缺少近光                                             | 调整三档颜色，叠加实色边框、近光、外光和轻内光；默认显示                                       |
| 图片像被放大截断     | 原实现虽然写了 contain，但嵌套 Grid 的隐式轨道及百分比高度存在固有尺寸参与撑高的风险，之后再由外层裁切 | 卡片设置可收缩的明确轨道，视觉盒建立定位包含块，图片容器填满该盒，图片自身不再参与卡片尺寸计算 |
| 标题到首排空白过大   | 结果区依赖视口的 min-height，同时网格 flex: 1、align-content: center，把剩余高度分给网格并将卡片居中   | 有结果时自然文档流；取消上述高度分配；空状态单独保留 280px 最小高度                            |
| 宽度、间距不协调     | 原最小高度 136px 与横向比例相互制约，较窄两列卡片也可能挤压信息栏                                      | 约 2.1:1、统一 28px 行列间距；≤640px 提前降为一列                                              |

图片撑高是静态代码风险判断，未用实际浏览器测量原图盒子的计算尺寸。不能把卡片自身的 overflow hidden 直接认定为自身 box-shadow 被裁切的原因；本轮检查的 App、main、页面及结果祖先没有专门裁切结果 Glow 的规则。现在明确划分外部发光与内部图片裁切职责，实际边缘效果仍需人工确认。

## 最终 CSS 与组件规则

- 新增纯展示组件 `WarpResults`，接收只读 entries、现有 presentation adapter 和 sourceLabel，向父级发送 details。正式页面和验收页使用同一结果标题、来源、网格及卡片，无第二套验收布局。
- 结果卡继续使用同一个 PrimeVue Button：宽 100%、约 2.1:1，列为 `minmax(0, 1fr) minmax(56px, 27%)`，行可收缩；不保留 136px 最小高度。单抽最大宽 620px，结构相同。
- 信息区 `repeat(3, minmax(0, 1fr))`，每槽居中，内边距 8px／6px；光锥中槽为空。普通 Icon 24px、星级 64×16px；单抽 Icon 为响应式 24–36px、星级最大 84×20px，并限制在槽位宽度内。
- UP 位于视觉区左上方 8px，11px 字号，独立背景与边框，不挤占命途／属性／星级槽。
- 卡片外层 overflow visible，负责 2px 边框、8px 圆角和阴影；只有内部视觉盒 overflow hidden，并沿用左侧圆角。视觉子容器相对盒子定位填充，Grid 与图片均允许收缩。
- `WarpItemVisual` 新增可选 crop，仅结果卡启用。角色在结果中 cover、center 40%；光锥 contain、center、8px／12px 内边距。详情角色仍 contain，头像模式保持不变。不按物品 ID 设置裁切，也不修改素材或 URL 映射。
- `WarpVisualIcon` 本身无需改动；尺寸约束仅在结果卡内设置，避免影响历史、详情或其他调用方。缺 URL、请求失败继续由现有 `useImageSource` 与中性占位处理。
- 桌面八列 Grid、卡片跨两列，第 1／8 项从第 2 列开始，第 4 项回第 1 列，得到顺序不变的 3–4–3。<1040px 为两列，≤640px 为一列。网格 28px 等间距、16px 内边距，网格及结果外层可见溢出。
- 结果区不分配剩余视口高度，主标题 19px、来源／抽数 13px。没有新增全站排版规则、固定大 margin-top 或绝对定位结果网格。
- 保留原 Tooltip、ARIA、触屏／Enter／Space 详情入口和返回焦点路径。保留批次 ID＋记录 ID key、180ms／7px 入场与逐张 50ms 延迟；reduced-motion 关闭动画。只有验收页的显式重播按钮会重新挂载同一固定场景。

主题 Token 继续集中于 preset，作用域只用于 Warp 结果卡：

| 稀有度 | 边框颜色  | 4px 近光混色 | 16px 外光混色 |
| ------ | --------- | ------------ | ------------- |
| 3★     | `#6489B4` | 20%          | 10%           |
| 4★     | `#CE8FFF` | 65%          | 32%           |
| 5★     | `#FFD17A` | 85%          | 46%           |

三档另有 12% 的 8px 内光。近／外光使用颜色与 transparent 混合，不依赖 Hover；Hover 只轻微调整背景，不改变尺寸。没有持续闪烁、倾斜或复杂动态光效。28px 间距为柔和衰减外光提供空间；是否相邻抢色或存在边缘裁切仍属于人工视觉验收。

## 确定性验收入口与数据隔离

使用 Node 24，执行 `npm run dev`，按终端实际地址打开 `/tests/manual/warp-results/index.html`。这是 Vite 开发入口，不注册生产路由，也不是 `npm run preview` 的验收页面。复用正式组件、PrimeVue preset、Tailwind 层顺序、双语消息和详情 Dialog，不调用抽卡 composable、引擎、RNG、存储或真实历史。

测试夹具按类别／稀有度筛选后按稳定 ID 排序，生成冻结的展示记录。每组记录的 id 与 batchId 确定，页面提供记录编号→物品 ID 的顺序表。全三星十连是特意构造的展示记录，不能当作符合十连保底规则的真实引擎结果。

**当前正式 Snapshot 不含五星光锥。** 为能检查该类别的五星样式，测试图中增加独立 `fixture:light-cone:5` 身份，使用明确的双语合成名称，复用按稳定 ID 选出的四星光锥封面及命途映射。只在测试数据副本中补充这一条，不改正式 Snapshot、候选池、Catalog、资源或引擎。页面显著说明这一限制；它不能证明真实五星光锥素材的构图已经通过验收。

## 维护者本地手工验收

1. 运行 `npm run dev`，打开终端地址下的 `/tests/manual/warp-results/index.html`。依次选 all-three、four-mixed、five-mixed，在鼠标移出卡片后比较蓝／紫／金三档，确认紫／金外光真实延伸、边缘柔和且没有被裁切。
2. 在 1440／1920px、100% 页面缩放下核对三排 3–4–3、十张等大、每排水平居中、28px 行间距和标题到首排的留白；展开顺序表，按从左到右、从上到下检查记录编号。切换单抽，检查最大宽与同一三槽结构。
3. 在 four-mixed 中对照第 2／5 张、第 3／6 张，再在 five-mixed 中对照第 1／6 张、第 3／7 张：UP 有无不能移动任何槽位，光锥的空属性槽不能让命途／星级靠拢。确认角色面部可辨、主体协调，光锥完整封面未被拉伸或裁切。
4. 浏览器开发者工具选卡片，检查计算样式的 `--p-warp-rarity-3/4/5`、border-color 和 box-shadow 确实解析到上述三档颜色，未被主题或父级覆盖；不要只看源码声明。
5. 检查 1024px 两列、640／390／320px 一列；补查 1040／1039px 与 641／640px 的断点两侧，确认无横向滚动、图标重叠、不同卡高、Glow 裁切或入场布局跳动。宽屏结果应遵循现有 app-shell 最大宽度，不另行扩展全站布局。
6. 中英文下切换场景、反复切换语言、Hover、触屏点击、Tab 后 Enter／Space 打开详情，Escape 退出并回到卡片。语言／详情／图片状态不应重播入场；只有显式「重播入场动画」按钮重播。用屏幕阅读器确认可访问名称、原生按钮与详情信息可达，光锥没有虚假属性。
7. 选 image-fallbacks，核对缺 URL、预期请求失败、中性占位和极端比例图都不撑开卡片，几何圆形保持比例；在系统／开发者工具启用 reduced-motion 后确认取消入场动画、保留静态 Glow。
8. 回到正式 `/warp-simulator`，检查空状态，完成星缘选择后做真实单抽／十连。查看详情、历史、语言切换与面板操作后，结果、历史计数和保底不得变化；核对真实抽取顺序及详情焦点恢复。人工确认原有重置与抽取交互无回归。

代码、构建与单元测试不能证明真实浏览器的构图、亮度、实际键盘焦点或屏幕阅读器行为已通过。当前交付停在等待维护者视觉／交互验收，不自动进入下一阶段。
