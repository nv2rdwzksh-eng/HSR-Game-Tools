## 特殊继承的建模与独立验证

目标是开拓者时，继承集合等于目标实际 Class 流派与 {2004, 2012} 的并集。MILP 对这两个固定授予流派直接使用目标选择变量 q，避免再与目标固有／星徽来源相加；其余流派仍通过 k = q AND targetPresence 精确线性化。姬子的最终 presence 继续采用来源相加并受不超过 selected 的约束，因而自身固有或佩戴星徽与继承冲突时非法。

独立评估器不读取 LP、列值或模型预测；从目标实际流派和声明的额外流派构造 Set，再与姬子自身来源检查冲突。只消除继承集合内部的重复，不掩盖自身来源冲突。普通目标、阵营／独立羁绊过滤及布洛妮娅限制不变。真实 HiGHS 的前后台测试都确认：没有另一流派星徽也能让姬子取得能量和欢愉；额外星徽流派正常继承，目标自己仍只贡献自己的实际羁绊。

## 配置排除、质量与最优性

每条 Cut 使用全部角色选择、角色星徽分配和领航员目标二元变量：已知为 1 的项取 -x，已知为 0 的项取 +x，下界为 1 减已知 1 的数量。变量由模型构建器生成，外部角色名／ID 不进入 LP 标识符。不包含任务标志、人数或 AND 辅助变量。星徽变量按角色和种类定义，本身不存在槽位排列自由度。

canonical signature 排序角色形态和各自星徽 ID，保留星徽归属、领航员目标和形态差别。结果层再次去重；所有模型约束也以结构化表达式保留，解码时核对每行，确保旧配置确实被排除。每候选还执行独立合法性、人数、任务完成与目标值验证；原有 1e-6 二元容差和 1e-5 目标值容差未放宽。

目标仍为 (3S+1)×完成数−星徽数。尚未证明最大完成数时添加已知最好完成数下界；后续提高完成数便清除低完成数候选，但保留其排除记录。证明后固定完成数。最终稳定排序完成数降序、星徽升序，只保留最高已知完成数，最多三个，不补入较低完成数配置。

证明将原始域分成已排除配置、当前搜索空间和低于质量下界的配置。排除配置都已独立验证，低于下界者不能改善字典序目标；只有结合这些证据的 optimal／穷尽才能得到原问题证明。完成全部任务可单独证明最大完成数，不等于星徽最少。批次的 maximumCompletedProven／minimumEmblemsProven 与候选的 subproblemOptimal 分开；候选还须达到原问题已证明的最好目标才标记 originalOptimal。即使后续子问题 optimal，星徽更多的候选也不冒充原问题最优。

## 时间、状态与兼容

使用一个单调 deadline，记录初始化、建模、搜索、解码与验证总耗时。首轮分配当时剩余的 75%；已有一个候选时下一轮取剩余一半，已有两个时取剩余全部；首轮没有 incumbent 时优先用剩余全部恢复首个结果。单方案包装直接用全部剩余时间。HiGHS runtime 在适配器内缓存，模型解析后重新扣除时间，原生模型 finally 释放。

正常预算结束返回本轮已验证候选。求解或验证错误不发布部分新批次，Session 保留历史完整有效批次；主动取消直接终止 Worker，只保留此前已返回的历史批次，本轮没有增量协议。请求 ID 阻止旧响应覆盖，配置改变整批 stale，失败／取消维持 historical，选中索引在新有效批次重置为 0。语言／候选切换和配置编辑都不触发求解。

保留 CLI 参数、输出单方案和退出码；仅将时间文案改为请求预算。新增 `npm run bench:currency-wars`，不新增依赖，也不改 HiGHS 版本。
