## 求解器与数学正确性

新增唯一精确依赖 `highs@1.15.3`，通过系统代理安装，保留唯一 npm 锁文件。已在 Node 24.21.0 下验证包的 ESM／Wasm 接口，无需原生扩展或服务。依据 [highs-js 官方接口](https://github.com/lovasoa/highs-js)和随包类型声明使用持久模型，`finally` 中释放模型。

采用 MILP：形态与星徽是二元变量；身份组最多选一个，角色数不超过槽位；星徽总预算与单角色三个槽位分开约束。角色羁绊人数由固有、星徽和特殊继承贡献相加，并限定单角色同一羁绊最多为一，因而冲突配置不可行，不用 OR 去重掩盖非法配置。

领航员目标变量只能指向另一名具有列车同行的角色。通过 AND 线性化，目标每一种最终流派都必须继承；阵营和独立类型从未建立继承变量。全部真实星徽参与候选，保留列车同行星徽的间接收益。布洛妮娅用其他角色的最终人数作比较，三种形态分别表达严格较多或平局；V1 禁止她作为领航员目标。

目标 `(3S + 1) × 完成任务数 − 星徽数` 保证一项任务的增益超过所有可能的星徽节省。任务标志建立双向人数约束，超时 incumbent 也不能任意遗漏已经满足的任务。MIP Gap 两项均设零。

独立计算器从确定阵容重新验证角色、星徽、身份、目标资格、继承类型、布洛妮娅形态、最终人数和任务。求解器结果另外比对人数表达式、任务标志和目标值。首次联调时，这一验证拦截了 LP 解析后列顺序与变量创建顺序不同的解码错误；最终改为通过变量名称查询 HiGHS 列位置。

模型状态和 primal 可行状态分开判断；无可行解的超时结果不会读取数值缓冲区。最优、可行未证最优、不可行、无结果和模型／数据错误分别输出。零搜索时限时，简单模型也可能在 presolve 阶段证明最优，因此测试不假设零时限必定没有解。
